# 治理

FlatPark 有意保持简单：一项改动不应该等比它需要的更多的人。日常工作，从上架新应用到下架，都只需要一个维护者，加上如实写明测了什么。只有修改规则和基础设施才需要更多人。

## 角色

- **维护者**有合并权限，负责应用目录、基础设施和规则。目前只有一位，就是项目的所有者（@jing2uo）。
- **贡献者**是其他所有参与的人：打包应用、测试、报告问题、完善文档。
- **开发者**对自己已上架的应用有最终决定权：要不要上架、怎么打包、怎么介绍。

## 谁同意什么

| 改动 | 需要什么 |
|---|---|
| 上游的新版本 | 不需要人：新文件能解包，CI 就自动合并 |
| 上架新应用、修改软件包、批量变更、下架 | PR 里写明测了什么、没测什么（[测试手册](../reviewers/testing-playbook.md)），由一位维护者合并 |
| 开发者对自己应用提的要求 | 照要求改，单独一个 PR |
| [原则](principles.md)、安全底线、签名、基础设施 | 有多位维护者时，需要另一位维护者同意 |
| 发现某个版本会窃取数据或破坏系统 | 任何维护者立即撤下；见[安全](security.md) |

- 核心功能没法测试的应用（需要账号、登录或我们没有的硬件），在开发者或能测试的人确认可用之前不上架。
- 下架要有明确理由，理由见[收录政策](policies.md#下架)。

## 成为维护者

打包和审核长期经得起检验的贡献者，会由现有维护者邀请。退出的维护者不再有合并权限，在历史记录里的位置保留。

## 基础设施

flatpark.org 域名，以及承载网站和软件仓库的 Cloudflare 账号（Pages、R2、Workers），目前由所有者个人提供。等项目有了长期伙伴，这些会迁到项目自己控制的账号下，让项目不依赖任何一个人才能运转。
