# 原则

这些原则来自[我们相信什么](about.md#我们相信什么)，文档里的每条规则又都来自其中某一条。遇到规则没覆盖的情况，就按这些原则来判断。

## 收录：只管伤害和诚实，不管品味

1. **合规就收。**应用是厂商的官方发布、没有恶意、可以合法分发、在沙箱里能用、包对自己做了什么说实话，满足这些就可以收录。
2. **不看出身。**不问用户多少、项目多老、谁写的、用什么写的。没有任何应用会因为它的 toolkit、许可证、开发方式，或者别人给它贴的标签而被拒绝或下架。
3. **替用户打包。**厂商没有参与，应用也可以收录：社区因为用户需要而打包，用的是厂商的官方下载。有人需要、但没有可用的官方 Linux 版本的应用，可以改由公开的[构建仓库](../packagers/basics.md#build-repositories)按上游的构建方式、在其许可范围内发布一个版本；它的问题反馈到这个仓库，绝不找上游。

## 信息：陈述事实，不下结论

4. **每个应用页都说清楚。**权限、包装等级、开源还是闭源、是否需要账号、有没有广告或付费功能、发版节奏、安装量，全部作为事实展示，不打分。
5. **每个包都说实话。**每个包都声明自己的包装等级（Unmodified、Adapted、Modified、Reduced isolation），CI 会核对声明和包的实际行为是否一致。闭源应用可能需要改动才能在沙箱里工作；改动要经过审核，应用页面会写清改了什么、为什么。

## 曝光：让好应用被看见

6. **推荐按公开规则来。**热门、精选、合集、指南都按任何人都能核实的公开信号排序，每条编辑精选都写明理由。小而好的应用有一条看得见的上升路径。
7. **沉下去，而不是删掉。**不再维护的应用会退出推荐，但仍然收录、仍然能装。只有应用坏了、下载没了、出现恶意版本，或者开发者要求时，才会下架。

## 便利：把 Flatpak 带给每个应用

8. **只用厂商自己的构建。**应用来自厂商的官方发布，安装时由你的 Flatpak 直接从厂商的服务器下载（extra-data）。FlatPark 不从源码构建应用，也不托管应用文件。开源应用原样运行：不向它的进程注入任何东西，不改它的任何文件。如果它不这样做就没法在沙箱里工作，应该由上游修复，修好之前不上架。
9. **一个地方安装和更新。**原本只提供 `.deb`、tarball 或 AppImage 的应用，通过同一个 remote 安装并自动更新，通常在上游发版后几分钟内就能更新。
10. **每个应用都用最新的 runtime。**freedesktop、GNOME 或 KDE runtime 出新版本时，用它的应用会一起升级并测试，你的磁盘上不会因为某个应用留着旧 runtime。
11. **默认最小权限。**软件包只授予应用主要功能所需的权限；更多权限由用户自己决定，文档里写好对应的命令。宽泛的权限（家目录、宿主命令）只有经过审核、应用确实需要，或者不给就要用户做太多 override 时，才默认授予。
12. **发布前测试，出问题快修。**我们自己的改动发布前要测试（[测试手册](../reviewers/testing-playbook.md)）；上游发版立即发布，出了问题快速修复。每个流程都用两个问题来衡量：能不能避免我们自己带着 bug 发布，会不会拖慢这个速度。

## 自我约束：FlatPark 管住自己

13. **开发者对自己的应用有最终决定权**：上不上架、怎么打包、怎么介绍。对别人的应用没有发言权。
14. **所有决定都公开。**规则、软件包、审核、排序、事故和下架都在公开仓库里，规则只通过公开的 PR 修改。
